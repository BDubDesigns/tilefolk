Tilefolk ActionOption Checklist

Goal: controllers choose an option ID, while the engine keeps ownership of the real server-generated action.

Open apps/server/src/simulation/controllers/types.ts.

Add a server-only option shape with id, description, and action.

export interface ActionOption {
  id: string;
  description: string;
  action: NpcAction;
}

Do not change ChooseActionOptions yet.

Create apps/server/src/simulation/getActionOptions.ts.

Its job: convert raw valid NpcAction[] into selectable ActionOption[].

  • move becomes move:n, move:ne, etc.
  • pickup becomes pickup:item_0.
  • wait becomes wait.
// Concept only, write it yourself:
getActionOptions(actions) => [
  { id: "move:n", description: "Move n", action: moveAction },
  { id: "wait", description: "Wait", action: waitAction },
]

Create apps/server/src/simulation/getActionOptions.test.ts.

Test these behaviors before wiring anything into stepWorld:

  • move action becomes option ID move:n
  • pickup action becomes option ID pickup:item_0
  • wait action becomes option ID wait
  • the original action is preserved in option.action
npm run test -- --run apps/server/src/simulation/getActionOptions.test.ts

Return to controllers/types.ts.

Change the controller input from raw actions to action options.

export interface ChooseActionOptions {
  world: World;
  npc: Npc;
  actionOptions: ActionOption[];
}

Change controller return type to string | null.

Open controllers/deterministicController.ts.

It should choose the first option and return that option's ID.

const firstOption = options.actionOptions[0];

if (firstOption === undefined) {
  return null;
}

return firstOption.id;

This file should no longer need to import NpcAction.

Open controllers/deterministicController.test.ts.

Tests should pass actionOptions, not raw actions.

  • first test expects selected ID, like "wait"
  • second test expects null

Open apps/server/src/simulation/stepWorld.ts.

New flow:

  • get raw valid actions with getValidActions
  • wrap them with getActionOptions
  • controller returns selected option ID
  • find matching option by ID
  • fallback to wait if no ID or no matching option
  • apply selectedOption.action with the existing switch

Run the full checks.

npm run test
npm run typecheck

Movement, pickup, wait, events, and turn tracking should still pass.
